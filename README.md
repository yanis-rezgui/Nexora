# Nexora

Nexora is a full-stack project and team management platform built for IT teams. It combines project/task tracking, role-based collaboration, real-time updates, and activity auditing in a single application — designed with the day-to-day workflow of a small engineering team in mind.

> 🚧 **Status**: actively developed by a solo developer. Core project/task/member management is implemented; the analytics dashboard is in progress.

## Overview

Nexora lets small teams and early-stage startups organize their work around **projects**, **tasks**, and **members** — with live updates instead of manual refreshing. It was built to explore a production-style architecture at a manageable scale: a few hundred users across several organizations, prioritizing simplicity of maintenance over premature complexity.

- **Live demo (frontend):** [nexora-virid-omega.vercel.app](https://nexora-virid-omega.vercel.app) <!-- update if the URL changes -->
- **Backend:** deployed on Render
- **Repository:** [github.com/yanis-rezgui/Nexora](https://github.com/yanis-rezgui/Nexora)

## Features

**Authentication & Authorization**
- Email/password authentication with JWT access + refresh tokens
- Tokens stored in `httpOnly` cookies (XSS-resistant)
- Refresh tokens persisted in the database with revocation support
- Project-level roles (Owner, Manager, Developer) plus a platform-level Admin role

**Project & Task Management**
- CRUD for projects, with owner/member access control
- Member invitation and role management per project
- CRUD for tasks with assignment, status transitions, labels, and comments
- File attachments via Cloudinary

**Real-Time Collaboration**
- WebSocket layer (Socket.io) authenticated via the same JWT cookies as the REST API
- Live task and notification updates pushed to connected clients
- Per-project rooms so updates are scoped to relevant users only

**Notifications & Activity**
- In-app notifications for assignments, status changes, comments, and mentions
- Project-level activity log (audit trail) with pagination

**Security & Reliability**
- `helmet` for secure HTTP headers
- Rate limiting on sensitive endpoints (`express-rate-limit`)
- Request validation with `zod`
- CI pipeline (lint + tests) running on every push

## Tech Stack

**Backend**
- Node.js 22 / Express 5
- PostgreSQL with Prisma ORM (`@prisma/adapter-pg`)
- Socket.io for real-time communication
- JWT (`jsonwebtoken`) + `bcrypt` for authentication
- `zod` for schema validation
- `helmet`, `cors`, `express-rate-limit` for security
- Cloudinary for media storage
- Resend / Nodemailer for transactional email

**Frontend**
- React + TypeScript
- React Router for routing
- Context API (Auth, Projects, Members, Tasks) for state management
- REST API consumption via `fetch` with credentialed requests

**Infrastructure**
- Render (backend hosting)
- Vercel (frontend hosting)
- Docker Compose for local development
- GitHub Actions for CI (lint + tests)

## Architecture

Nexora follows a fairly standard layered Express architecture:

```
Client (React) ⇄ REST API (Express) ⇄ PostgreSQL (via Prisma)
                        │
                        └─ Socket.io (WebSocket, JWT-authenticated)
```

- **Routes** map HTTP endpoints to controllers.
- **Controllers** contain request handling and access-control checks (project ownership/membership).
- **Prisma** provides a typed data layer over PostgreSQL, using the `pg` driver adapter.
- **Socket.io** shares the same JWT cookies as the REST API, so a single login session drives both HTTP and real-time access. Users join a personal room (`user_<id>`) and per-project rooms (`project_<id>`) on connection; admins additionally join an `admins` room.

## Data Model

Core entities (Prisma schema):

| Model | Purpose |
|---|---|
| `User` | Account, credentials, profile |
| `RefreshToken` | Persisted refresh tokens with revocation |
| `Project` | A project owned by a user |
| `ProjectMember` | Join table linking users to projects with a role (`MANAGER`, `DEVELOPER`) |
| `Task` | Work item belonging to a project, with status and assignee |
| `Comment` | Comments on tasks |
| `Attachment` | Files attached to tasks (Cloudinary-hosted) |
| `Label` | Tags applied to tasks |
| `Notification` | Per-user notifications generated by task/project events |
| `ActivityLog` | Audit trail of actions taken within a project |

## Getting Started

### Prerequisites
- Node.js 22.x
- PostgreSQL (or use the provided `docker-compose.yml`)
- npm

### 1. Clone the repository
```bash
git clone https://github.com/yanis-rezgui/Nexora.git
cd Nexora
```

### 2. Start PostgreSQL (optional, via Docker)
```bash
docker compose up -d
```

### 3. Backend setup
```bash
cd backend
npm install
cp .env.example .env.development.local   # see Environment Variables below
npx prisma generate
npx prisma migrate dev
npm run dev
```
The API will be available at `http://localhost:5000`.

### 4. Frontend setup
```bash
cd frontend
npm install
npm run dev
```

## Environment Variables

Create a `.env.development.local` file in `backend/` with the following keys:

```bash
NODE_ENV=development
PORT=5000

DATABASE_URL=postgresql://user:password@localhost:5432/nexora

ACCESS_TOKEN_SECRET=
REFRESH_TOKEN_SECRET=
ACCESS_TOKEN_EXPIRATION=
REFRESH_TOKEN_EXPIRATION=

CLOUDINARY_CLOUD_NAME=
CLOUDINARY_API_KEY=
CLOUDINARY_API_SECRET=

RESEND_API_KEY=

CLIENT_URL=http://localhost:5173
```

> ⚠️ Never commit `.env*` files — they're already excluded via `.gitignore`. Keep a `.env.example` (no real values) in the repo so contributors know which keys are required.

## API Overview

All endpoints are versioned under `/api/v1`.

| Resource | Base path | Description |
|---|---|---|
| Auth | `/api/v1/auth` | Sign up, sign in, sign out, current user |
| Projects | `/api/v1/projects` | Project CRUD |
| Members | `/api/v1` | Project membership management |
| Tasks | `/api/v1` | Task CRUD, assignment, status |
| Comments | `/api/v1` | Task comments |
| Labels | `/api/v1` | Task labels |
| Notifications | `/api/v1` | User notifications |
| Dashboard | `/api/v1` | Aggregated project/task data |
| Settings | `/api/v1` | User/account settings |
| Admin | `/api/v1` | Platform administration |

Authentication is cookie-based; no `Authorization` header is required once logged in.

## Real-Time Events

Socket.io connections are authenticated using the same `accessToken` cookie as the REST API. On connection, a client automatically joins:

- `user_<userId>` — for personal notifications
- `project_<projectId>` — after emitting `project:join`, for live task/comment updates on that project
- `admins` — if the authenticated user has the `ADMIN` role
